# st 技能使用指南

## 核心功能
将复杂的研究生水平专业概念，转化为通俗易懂、富有启发性的寓言故事，降低理解门槛，同时保留概念的核心本质。

## 使用流程
1. **概念选择**：
   - 如果用户指定了具体概念/领域，优先使用用户指定的内容
   - 如果用户未指定，随机从计算机科学、经济学、心理学、生物学、物理学等领域选择一个研究生水平的概念（避免过于基础的本科/高中知识点）
   
2. **故事创作要求**：
   - 故事结构完整，有人物、情节、冲突、结局
   - 全程不提前透露核心概念，所有概念要素都转化为故事中的具体意象
   - 直到故事接近尾声时，才自然引出对应的专业概念
   - 故事长度控制在300-800字，简洁生动，避免冗长

3. **解释部分要求**：
   - 故事结束后，首先用100-200字清晰解释所选的专业概念本身（包括定义、核心逻辑、适用场景）
   - 然后逐一列出故事中的每个关键隐喻对应的实际含义，对应关系清晰明确
   - 最后补充1-2句这个概念在现实中的应用价值

## 质量标准
✅ 概念准确：所选概念确实属于对应领域研究生阶段的知识点，解释专业无误
✅ 隐喻恰当：故事中的意象与概念的核心要素一一对应，没有强行关联
✅ 悬念充足：不到故事结尾读者无法直接猜到讲的是什么概念
✅ 通俗易懂：故事不需要专业背景就能看懂，解释部分兼顾专业性和可读性

## 示例输出结构
```
## 老鞋匠的秘方
（故事内容：讲述老鞋匠做鞋子永远比别人耐用，学徒偷学发现他每次都会在鞋跟处多钉两颗不起眼的钉子，但只有客户穿着超过3个月才会感受到差别，很多同行都因为省这两颗钉子丢了老客户...）

---

### 核心概念：鲁棒性（Robustness）
鲁棒性是控制系统和软件工程中的核心概念，指系统在遇到异常输入、硬件故障、网络波动等极端情况时，仍然能够保持正常运行的能力，而非直接崩溃或产生错误输出。它是系统可靠性设计的重要考量指标，广泛应用于航空航天、金融交易系统、工业控制等容错要求高的领域。

### 隐喻对应：
- 鞋子 → 软件/控制系统
- 多钉的两颗钉子 → 冗余设计、异常处理机制
- 3个月穿着的极端场景 → 系统运行中的异常输入、故障场景
- 耐用不磨坏 → 系统鲁棒性强，极端情况下仍能正常工作
- 同行省钉子丢客户 → 忽略鲁棒性设计的系统在长期运行中容易出现问题，造成损失

### 应用价值：
在高可靠性要求的系统设计中，看似冗余的鲁棒性设计虽然会增加少量前期成本，但能大幅降低长期运行中的故障风险和维护成本。
```
